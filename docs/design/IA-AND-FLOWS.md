# Navigation and flows

The Command Deck is the activity host. It retains existing non-exported activities as destinations to preserve verified platform flows. It does not claim the whole repository was converted to Compose: App control and Integrations remain classic Views.

```
fR3k host
  APP MODS → search / categories / live requirements → numbered walkthrough
  Deck → observed state / start-stop HUD / Commands / Ask / limits
  Planes → Bridge / Patch / Shell / Root → bootstrap lab / guides
  Workflows → select registered capabilities → exact-target review → run → receipts
  Agent → local MCP lifecycle / bearer token / actual server tool descriptions
  Journal → filter operations → outcome / identity / actual inverse
  Tools → all supporting activities, each with explanation and requirements
```

Every guide: one tap to catalogue, one tap to expand after scrolling or search. Guide visibility is category/filter dependent, not an invented capability count. Each tool destination states prerequisites before launch and has an in-context help affordance.

| Journey | Annotated flow | Recovery |
|---|---|---|
| First run | Setup → permission explanation → Android grant → Deck observed readiness | Skip optional setup; revisit Tools → Setup; never report missing grants as ready. |
| Skip an ad | APP MODS → skip guide → read fixture-only boundary → reviewed fixture capability | Fingerprint/postcondition refusal stops the run; unmask reverses a mask, skipping itself is a tap. |
| Change owned app | Tools → App control → inspect → prepare → floating review → Android installer | Review data loss before reinstall; archive restoration remains installer-reviewed. |
| Automate chore | APP MODS → AUTOMATE → app-map guide → declared entry-point exploration via MCP | Re-record on target update; stale/ambiguous identities are refused. |
| Fuse two apps | Workflows → add ordered capabilities → inspect each target and inverse → checkbox → run → Journal | Stops on failure; inspect the recorded inverse of successful steps. Draft is session-local. |
| Shell tier | Planes → shell explanation → App control → display bootstrap command → authorised host ADB | Recheck observed tier; restart service after process/reboot loss. |
| Root tier | Planes → root explanation → root shell bootstrap → root-gated operation | Shell tier refuses root-only actions; root is observed from actual server UID. |
| OpenCode Go | Tools → Settings/provider → masked key state → save → tool-capable model → TEST | Remove key or change provider preference; never expose key in evidence logs. |
| Own agent | Agent → start MCP → reveal bearer deliberately → connect localhost client → inspect tools | Stop MCP; reads and writes still obey target identity and execution approval rules. |
| Screenshot | Tools → Screenshot → Capture screen → system consent → actual PNG preview | Save real bytes / Share chooser / delete private image; cancellation and unsupported analysis are explicit. |
| Floating workspace | Start HUD → orb → chat/browser/terminal/radial → drag title / resize corner | Outside taps reach app beneath; close window independently; stop HUD removes service overlays. |

The stack model is interactive in Planes and Workflows: App UI → Plan → Capability → Plane → Target. Selecting a stage explains what it contributes; it is educational, not a simulated execution trace.

## Release scope update

Current normal UI uses installed-app selection, identity-bound controls/maps, compatible module import, wireless shell and nine production procedures. Fixture walkthroughs are debug instrumentation-only. Obsolete external privilege/patch-manager setup has been removed from Connections. Internal patch-engine attribution remains necessary. Earlier fixture-specific examples in this document describe lab verification, not default release navigation. See CONTINUATION.md for actual completed/pending acceptance and ROUTING-MATRIX.md for current support.
